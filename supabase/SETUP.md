# ربط منصة طلاقة بـ Supabase

تستخدم صفحات دخول المعلمين ولوحة المالك Supabase Auth وقاعدة بيانات Supabase. لا تنشر مفاتيح `service_role` أو `secret` في ملفات الموقع أو GitHub.

## 1. إعداد قاعدة البيانات

1. افتح مشروع Supabase ثم **SQL Editor → New query**.
2. انسخ محتوى `schema.sql` كاملًا ونفّذه.
3. بعد `schema.sql`، نفّذ `migrations/20261107140000_school_manager_access_scope.sql` من SQL Editor. يضيف هذا الترحيل إدارة مدير المدرسة، والحقول المسندة، وتقييد تقارير RLS بالصفوف. عند تحديث مشروع قائم، شغّل كل الترحيلات التي لم تُطبّق بترتيبها الزمني.
4. من **Authentication → Providers → Email** فعّل البريد الإلكتروني. يلزم إعداد SMTP موثوق إذا أردت وصول دعوات المعلمين إلى بريدهم.
5. من **Authentication → URL Configuration** أضف عنوان الموقع المنشور إلى Site URL وRedirect URLs؛ مثل `https://OWNER.github.io/REPOSITORY/`.

كل مشروع Supabase مخصص لمدرسة واحدة. في أول دعوة يحددها المالك، يُثبّت اسم المدرسة للمشروع، ويجب أن تطابقه الدعوات اللاحقة. الجداول مفعّل عليها RLS. لا يحصل حساب المعلم أو مدير المدرسة على صلاحيات الدخول حتى يفتح رابط دعوة Supabase الوارد إلى بريده، ينشئ كلمة المرور، وتؤكد قاعدة البيانات قبول الدعوة. تفعيل الحساب من لوحة الإدارة وحده لا يتجاوز قبول الدعوة. يستطيع المالك وحده إنشاء مدير مدرسة ومنحه `manage_teachers`؛ ويمكن للمدير دعوة معلمي المدرسة نفسها ومنحهم صلاحيات تقع ضمن صلاحياته وصفوفه ومواده فقط. صلاحيتا `reports` و`analytics` مستقلتان؛ ويقيد RLS تقارير الطلاب والتحليلات بالصفوف المسندة. لا تحمل سجلات الاختبارات الحالية بيانات المدرسة أو المادة، لذلك حقل المدرسة يعرّف المدرسة الوحيدة للمشروع، والمواد بيانات إسناد؛ أما حدود تقارير الاختبارات فتُفرض حسب الصف. ولا تظهر تذاكر الدعم إلا لحساب يملك صلاحية `support`.

بعد الترحيل، تُترك إسنادات الصفوف للحسابات القديمة فارغة عمدًا. على المالك فتح «صلاحيات المعلمين والمعلمات» وتعيين الصفوف والصلاحيات اللازمة لكل معلم قبل أن تظهر له التقارير.

إيقاف الحساب لا يحذف سجل المستخدم. وتتحقق سياسات RLS من حالة الحساب النشطة عند كل طلب، لذلك لا يعتمد منع الوصول إلى البيانات على انتهاء صلاحية JWT أو حذف مستخدم Auth.

## 2. إنشاء حساب المالك

1. من **Authentication → Users → Add user** أنشئ حسابًا بالبريد `brraa.20@gmail.com` وكلمة المرور التي تختارها.
2. بعد إنشاء المستخدم، افتح **SQL Editor → New query** وشغّل محتوى `owner-setup.sql`. ينشئ الملف أو يحدّث سجل `profiles` مباشرة من مستخدم Supabase Auth، ويعيّن هذا الحساب مالكًا نشطًا بكامل الصلاحيات، ويتوقف بخطأ إن لم يجتز السجل التحقق، ثم يعرض حالة الحساب وسجل الصلاحيات. يجب تشغيله من SQL Editor بصلاحية إدارية؛ سياسات RLS تمنع التحقق من هذا السجل من دون تسجيل دخول مخوّل.
3. في المشاريع القائمة، نفّذ ترحيل `20261107130000_ensure_platform_owner_profile.sql` أيضًا. بعد نشره، تعيد الواجهة إنشاء سجل المالك تلقائيًا إذا كان مفقودًا، بعد التحقق من أن جلسة Supabase تخص `brraa.20@gmail.com`. تأكد أن إعداد الموقع يشير إلى المشروع نفسه الذي طُبّق عليه الترحيل.

لا يمكن لمالك المنصة تحديد دوره من صفحة الموقع؛ الدور لا يعيّنه إلا مسؤول المشروع في Supabase.

## 3. نشر وظيفة دعوة المعلمين

تحتاج حسابات المعلمين دعوة بالبريد؛ كلمة المرور يختارها المعلم بنفسه عبر رابط الدعوة الذي ينشئه Supabase Auth. لا تُرسل كلمة المرور المؤقتة عبر قاعدة البيانات. لا تُمنح صلاحيات لوحة المعلم قبل التحقق من الدعوة وتسجيل قبولها في قاعدة البيانات.

1. ثبّت Supabase CLI من المصدر الرسمي، ثم افتح PowerShell داخل مجلد المستودع.
2. سجّل الدخول واربط المشروع:

```powershell
supabase login
supabase link --project-ref PROJECT_REF
```

3. انشر الوظيفة:

```powershell
supabase functions deploy create-teacher
```

تستخدم الوظيفة `SUPABASE_SERVICE_ROLE_KEY` سرًا داخل بيئة Supabase فقط، وتتحقق من جلسة المستخدم ومن كونه المالك قبل إرسال أي دعوة.

## 4. إعداد الواجهة العامة

من **Project Settings → API** انسخ **Project URL** والمفتاح العام **Publishable key** (أو مفتاح `anon` القديم) وضعهما في `supabase/config.js`:

```js
window.TalalaSupabaseConfig = Object.freeze({
    url: 'https://PROJECT_REF.supabase.co',
    publishableKey: 'sb_publishable_...'
});
```

استبدل القيم بالمشروع الفعلي، ثم اختبر الموقع على HTTPS. هذه القيم مخصصة لواجهة المتصفح؛ أمان قاعدة البيانات يعتمد على RLS وليس على إخفاء المفتاح العام.

لا تضع `service_role` أو `secret key` في هذا الملف. لا تُفعّل أو تنشر المنصة قبل إعداد القيم، دعوة المالك، وتشغيل فحوص الموقع.

## حذف البيانات يدويًا

يستطيع المالك حذف سجل طالب من لوحة المعلم. ولحذف كل النتائج أو التذاكر من SQL Editor:

```sql
delete from public.assessment_attempts;
delete from public.support_tickets;
```
